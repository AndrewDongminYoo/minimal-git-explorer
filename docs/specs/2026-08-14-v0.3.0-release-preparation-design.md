# Version 0.3.0 Release Preparation Design

## Goal

Prepare Minimal Git Explorer `0.3.0` as a locally verified VS Code Marketplace release candidate without creating a tag, pushing the release branch, creating a GitHub Release, or publishing to the Marketplace.

## Current State

The Marketplace currently serves version `0.2.0`, and the latest repository tag is `v0.2.0`.
The `main` branch points to merge commit `fb214a8416c5e455fe7750d24b396a1dab86fab5`, which includes the review-hardening work from PR #2.
The release range since `v0.2.0` contains a feature commit for view icons, dependency and security maintenance, repository lifecycle improvements, and Git correctness fixes.
There is no tag-triggered or Marketplace publishing workflow in `.github/workflows/ci.yml`; publication remains a separate manual operation.

## Version Decision

The target is `0.3.0`.
A patch release would understate the feature addition present in `v0.2.0..main`, while `1.0.0` would imply a stability milestone outside this work.
The higher VS Code host requirement is documented prominently because version `0.3.0` requires VS Code `1.125.0` or newer.

## Release Metadata

`package.json` will carry version `0.3.0`.
Its repository, homepage, and issue tracker URLs will point to `https://github.com/AndrewDongminYoo/minimal-git-explorer`, which is the verified repository serving the current `main` branch.
The Marketplace publisher identifier remains `dongminyu`; that identifier is independent of the GitHub account name.
The manifest integration test will protect all three GitHub URLs and the existing VS Code engine contract.

## Release Notes

The current `[Unreleased]` section in `CHANGELOG.md` will become `[0.3.0] — 2026-08-14`.
It will cover the entire `v0.2.0..main` range rather than only PR #2: view icons, Workspace Trust and CI coverage, the VS Code minimum-version change, dependency and security maintenance, stable stash identity, repository rediscovery, parsing correctness, fail-closed errors, unborn repositories, signal diagnostics, missing workspace roots, provider state, and virtual document cleanup.
`CLAUDE.md` will identify `0.3.0` as the current manifest version.

## Verification

The release candidate must pass a frozen dependency install, TypeScript checking, ESLint, the production build, VS Code tests on `1.125.0` and `stable`, dependency audit at high severity, Trunk checks, and `git diff --check`.
The VSIX will be written outside the repository, inspected for the expected runtime and user-facing files, and hashed with SHA-256.
The Marketplace will be queried after packaging to confirm that the published version remains `0.2.0`.

## External-Effect Boundary

This preparation does not authorize a commit, push, tag, GitHub Release, or Marketplace publication.
Those operations require a separate explicit request after the local candidate and evidence are reviewed.
