# Version 0.3.0 Release Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a locally verified Minimal Git Explorer `0.3.0` release candidate without publishing it.

**Architecture:** Treat the manifest and CHANGELOG as the release source of truth, protect Marketplace links with the existing manifest integration suite, and write the generated VSIX outside the repository. Preserve the current manual publication boundary.

**Tech Stack:** TypeScript, VS Code Extension API, pnpm 11, `@vscode/test-cli`, `@vscode/vsce`, esbuild, GitHub Actions, and Trunk.

## Global Constraints

- Target version is `0.3.0`.
- Minimum supported VS Code version remains `1.125.0`.
- Marketplace publisher remains `dongminyu`.
- Canonical source repository is `https://github.com/AndrewDongminYoo/minimal-git-explorer`.
- Do not commit, push, tag, create a GitHub Release, or publish to the Marketplace in this plan.
- Keep generated VSIX files outside the repository.

### Task 2: Verify the Release Candidate

**Files:**

- Verify: `package.json`
- Verify: `pnpm-lock.yaml`
- Verify: `.vscodeignore`
- Create outside repository: `/tmp/minimal-git-explorer-v0.3.0/minimal-git-explorer-0.3.0.vsix`

**Interfaces:**

- Consumes: the synchronized `0.3.0` manifest and the repository's existing release commands.
- Produces: full gate evidence, an inspected VSIX, and a SHA-256 digest without external publication.

- [x] **Step 1: Run static and package gates**

Run:

```bash
pnpm run check-types
pnpm run lint
pnpm run package
pnpm audit --audit-level high
TRUNK_TELEMETRY=off TRUNK_SENTRY=off CI=true trunk check --all
git diff --check
```

Expected: every command succeeds with no high-severity vulnerability or Trunk finding.

- [ ] **Step 2: Run both supported VS Code hosts**

Run:

```bash

```

Expected: the full extension test suite passes on both hosts.

Result: `[PARTIAL]` VS Code `1.125.0` and stable `1.133.0` each reported 62 passing tests and an extension-host exit code of 0, but the macOS parent `Code` process remained alive after the test host exited, so both wrapper commands required SIGINT and did not return exit code 0.

- [x] **Step 3: Build the VSIX outside the repository**

Run:

```bash

```

Expected: `vsce` produces the exact `0.3.0` VSIX path.

- [x] **Step 4: Inspect the package and hash it**

